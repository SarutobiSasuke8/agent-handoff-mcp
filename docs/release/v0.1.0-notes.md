# Agent Handoff MCP v0.1.0

First public release of `@sarutobi-sasuke/agent-handoff-mcp`, a local-first
MCP server for bounded, auditable handoffs between AI agents. Published to npm
with provenance through npm trusted publishing, and listed in the MCP Registry
as `io.github.SarutobiSasuke8/agent-handoff-mcp`.

## Install

```bash
npx -y @sarutobi-sasuke/agent-handoff-mcp help
```

Requires Node 22.13 or later. Start with `docs/QUICKSTART.md`.

## What is in it

- An MCP server over Streamable HTTP and stdio, with six tools:
  `handoff_whoami`, `handoff_send`, `handoff_inbox`, `handoff_get`,
  `handoff_acknowledge` and `handoff_update_status`.
- An operator-provisioned agent registry with explicit relationships and
  per-pair disclosure ceilings. Unknown keys, duplicates and malformed expiry
  data are rejected with field-specific, redacted errors.
- Bearer tokens stored only as SHA-256 digests, with an expiry. Raw tokens are
  shown once at issue time and never written to disk.
- Policy is rechecked on every tool call on both transports, so revoking,
  disabling or expiring an identity takes effect on live sessions without a
  restart.
- Actor-scoped lifecycle: the sender may cancel; the recipient may accept,
  block or complete.
- SQLite persistence with an append-only event log, idempotent sends and a
  reply-depth guard against agent loops.
- The `agent-handoff-mcp` CLI: `http`, `stdio`, `token`, `validate`, `init`,
  `issue`, `rotate`, `enable`, `disable`, `revoke`, plus backup and restore
  (`docs/RECOVERY.md`).
- Opt-in operational metrics, versioned store schema migrations, and a pinned
  MCP conformance gate (`docs/CONFORMANCE-2026-10-21.md`).

## Compatibility note: `expires_at` needs seconds

Zod 4.6.7 (#68) tightens datetime validation. Registry `expires_at` values,
and the `--expires` value for `issue` and `rotate`, must now include seconds.

| Value | Before #68 | v0.1.0 |
| --- | --- | --- |
| `2027-01-01T00:00:00Z` | accepted | accepted |
| `2027-01-01T00:00:00.000Z` | accepted | accepted |
| `2027-01-01T00:00:00+01:00` | accepted | accepted |
| `2027-01-01T00:00Z` | accepted | rejected |
| `2027-01-01T00:00+01:00` | accepted | rejected |

A rejected value fails `validate` and startup with
`agents[N].expires_at: value is not an ISO 8601 datetime with timezone offset`.
The published `schema/agent-registry.schema.v1.json` carries the same pattern.
No package has been published before, so this only affects registries written
by hand from a source checkout. To check one, run:

```bash
npx -y @sarutobi-sasuke/agent-handoff-mcp validate --registry /path/to/agents.yaml
```

## Package contents

55 files, about 46 kB packed and 151 kB unpacked: compiled `dist/src/`,
`scripts/generate-token.mjs`, `config/agents.example.yaml` (disabled example
identities with placeholder hashes), the registry JSON Schema, five documents
from `docs/`, and the top-level README, CHANGELOG, SECURITY, ROADMAP,
CONTRIBUTING and LICENSE. No tests, `.env` files, databases or local data.

## Verification

- CI on Ubuntu and Windows, Node 22.13.1, 22.x and 24.x: 54 unit tests and 10
  end-to-end tests, including a clean-room install of the packed tarball
  driving both transports.
- Release evidence (tarball, SHA-256 checksum, SPDX SBOM) is attached to the
  Release workflow run as the `release-evidence` artefact.

## Known limits

- The stdio transport and local SQLite store are the supported path. The
  experimental Postgres store (#60) is not part of this release.
- Node prints an `ExperimentalWarning` for `node:sqlite` on Node 22. It is
  harmless.
